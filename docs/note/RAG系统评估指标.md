# RAG 系统评估指标

> 类型：通用知识笔记  
> 适用范围：法律 RAG 的离线评测、回归测试与上线验收  
> 更新日期：2026-10-15

## 1. 指标全景

RAG（Retrieval-Augmented Generation）系统不能只看一个分数。完整评测至少覆盖以下五层：

| 层级 | 要回答的问题 | 常用指标 |
|---|---|---|
| 检索质量 | 正确法条找全了吗、无关结果多吗、正确结果是否靠前？ | Recall@K、Precision@K、Hit Rate@K、MRR、NDCG@K |
| 答案质量 | 最终回答是否正确、完整、切题？ | Answer Correctness、Completeness、Relevance |
| 证据质量 | 回答是否真正受到引用法条支持？ | Citation Validity、Citation Correctness、Citation Coverage、Faithfulness |
| 安全与法律质量 | 是否正确拒答，法律是否现行有效，是否泄露隐私？ | 拒答准确率、误答率、时效正确率、敏感信息泄露率 |
| 系统运行质量 | 是否足够快、稳定且经济？ | P50/P95 延迟、成功率、吞吐量、可用性、单次请求成本 |

可以把这套指标概括为：

```text
用户问题
  -> 检索：找得全、找得准、排得前
  -> 生成：说得对、说得完整、与问题相关
  -> 引用：引文真实、引用正确、结论有证据
  -> 运行：速度、稳定性、成本与安全合格
```

## 2. 检索评估指标

检索指标依赖“标准答案集”。对每个评测问题，先由标注人员确定所有应命中的法律和条文，记为相关集合 `G`；系统返回的前 K 条结果记为 `R@K`。

### 2.1 Recall@K：前 K 条找全了多少

公式：

```text
Recall@K = |G 与 R@K 的交集| / |G|
```

例子：某问题有两条标准法条 `A、B`，系统前 5 条返回：

```text
X、A、Y、B、Z
```

命中两条标准法条，因此：

```text
Recall@5 = 2 / 2 = 1.0
```

如果前 5 条只有 `A`，则 `Recall@5 = 1 / 2 = 0.5`。

多道题通常先逐题计算，再取宏平均：

```text
Macro Recall@K = 各题 Recall@K 之和 / 题目数
```

Recall@K 重点衡量“少漏掉正确法条”。它不直接惩罚前 K 条里混入的无关结果。

### 2.2 Precision@K：前 K 条有多干净

公式：

```text
Precision@K = |G 与 R@K 的交集| / K
```

沿用上面的例子，前 5 条中有 2 条相关：

```text
Precision@5 = 2 / 5 = 0.4
```

Precision@K 重点衡量“少返回无关法条”。在法律 RAG 中，若人工标准答案没有标全，实际相关法条可能被错误地算成无关结果，因此使用该指标前必须保证相关性标注比较完整。

### 2.3 Hit Rate@K：前 K 条是否至少命中一条

单题只有 0 或 1：

```text
Hit@K = 1，前 K 条至少有一条正确结果
Hit@K = 0，前 K 条没有正确结果
```

多题的 Hit Rate@K 是命中题数除以总题数。它适合“只要找到一条入口证据即可”的场景，但不能衡量多条法条是否找全。

### 2.4 MRR：第一条正确结果是否足够靠前

MRR 全称 Mean Reciprocal Rank，即平均倒数排名。先对每道题计算：

```text
RR = 1 / 第一条正确结果的排名
```

| 第一条正确结果排名 | RR |
|---:|---:|
| 1 | 1.000 |
| 2 | 0.500 |
| 3 | 0.333 |
| 5 | 0.200 |
| 未命中 | 0 |

再对所有问题的 RR 取平均：

```text
MRR = 所有问题 RR 之和 / 题目数
```

MRR 越接近 1，说明用户越容易在靠前位置看到第一条正确法条。MRR 只看第一条命中，不衡量多条正确法条是否找全，因此应与 Recall@K 搭配使用。

### 2.5 NDCG@K：整体排序质量

NDCG@K 同时考虑：

- 相关结果是否排在前面；
- 不同结果可以具有不同相关等级，例如“直接依据”“补充依据”“弱相关”；
- 理想排序与实际排序的差距。

取值通常在 0 到 1 之间，越接近 1 越好。只有“正确/错误”二元标注时，MRR 和 Recall@K 往往更直观；存在多级相关性标注时，NDCG@K 更有价值。

## 3. 答案质量指标

### 3.1 Answer Correctness：答案正确性

评价最终答案中的事实和法律结论是否正确。它与检索正确不是一回事：系统可能找到了正确法条，但仍然错误概括适用条件、例外、期限或法律后果。

可采用分级评分：

| 分数 | 含义 |
|---:|---|
| 2 | 结论正确，关键条件和例外完整，没有实质性错误 |
| 1 | 核心结论基本正确，但存在重要遗漏或轻微不准确 |
| 0 | 核心结论错误、无依据，或者回答不可用 |

报告结果时必须说明评分规则、部分正确如何处理，以及评分者是否具备法律专业背景。

### 3.2 Completeness：答案完整性

评价标准答案中的关键要点是否都被覆盖：

```text
Completeness = 已覆盖的关键要点数 / 应覆盖的关键要点总数
```

例如一个问题需要说明“适用主体、时间条件、赔偿后果”三个要点，回答只覆盖前两个，则完整性为 `2/3`。

### 3.3 Answer Relevance：答案相关性

评价回答是否直接解决用户问题，是否包含大量无关内容。正确但严重跑题的回答，相关性仍然较低。

## 4. 引用与忠实度指标

引用评估需要区分几个容易混淆的概念。

### 4.1 Citation Validity：引用有效性

检查引用对象是否真实存在并可追溯，例如：

- 法律名称和条号存在；
- `evidence_id` 能映射到原始 `chunk_id`；
- 展示的引文确实是原文中的连续内容；
- 没有伪造来源。

本项目当前的程序化引用校验主要覆盖这一层。

### 4.2 Citation Correctness：引用正确性

检查某条引用是否真的支持它所对应的主张。引用是真实法条，并不代表引用使用正确。

例如：

```text
主张：所有劳动合同都可以约定六个月试用期。
引用：《劳动合同法》第十九条。
```

法条虽然真实，但并不支持“所有劳动合同”这一概括，因此引用正确性不合格。

### 4.3 Citation Coverage：引用覆盖率

先把答案拆成需要证据支持的独立主张，再计算：

```text
Citation Coverage = 有引用支持的主张数 / 需要引用的主张总数
```

若答案有 4 个法律主张，只有 3 个附有相应证据，则引用覆盖率为 `3/4 = 0.75`。

### 4.4 Faithfulness：答案忠实度

评价答案中的主张能否从提供给模型的证据中推出，是否发生无依据扩写、过度推论或幻觉。

常见的逐主张算法是：

```text
Faithfulness = 被证据蕴含的主张数 / 所有需要证据的主张数
```

Citation Coverage 关心“有没有引用”，Faithfulness 关心“证据是否真的支持”。两者不能互相替代。

## 5. 拒答、安全与法律领域指标

### 5.1 拒答评估

把问题分为“应回答”和“应拒答/追问”，形成混淆矩阵：

| 真实情况 | 系统回答 | 系统拒答或追问 |
|---|---|---|
| 应回答 | 正确回答 | 过度拒答 |
| 应拒答 | 危险误答 | 正确拒答 |

重点指标包括：

- 正确拒答率：应拒答问题中，被正确拒答的比例；
- 过度拒答率：应回答问题中，被错误拒答的比例；
- 危险误答率：应拒答问题中，系统仍给出确定结论的比例；
- 追问有效率：缺少关键事实时，提出的追问是否能补足判断条件。

### 5.2 法律时效与来源治理

法律 RAG 还应单独评估：

- 法律时效正确率：引用版本在问题对应时间点是否有效；
- 权威来源率：证据是否来自官方或经过审核的来源；
- 版本匹配率：是否正确处理修订前后条文；
- 跨法条完整性：是否同时覆盖实体法、程序法或关联法律；
- 可追溯率：回答能否追溯到法律名称、版本、条号、原文和来源文件；
- 敏感信息泄露率：输入、日志和输出是否暴露个人敏感信息。

这些指标不能由普通 Recall@K 或答案流畅度替代。

## 6. 系统运行指标

| 指标 | 含义 |
|---|---|
| P50 延迟 | 一半请求能在该时间内完成，代表典型体验 |
| P95/P99 延迟 | 95%/99% 请求能在该时间内完成，反映长尾性能 |
| 成功率 | 请求成功完成的比例 |
| 可用性 | 服务在统计周期内可正常使用的时间比例 |
| 吞吐量 | 单位时间可处理的请求数，例如 QPS |
| 超时率 | 因外部模型、向量库等超时而失败的比例 |
| 单次请求成本 | Embedding、Rerank、LLM 和基础设施的平均成本 |

平均延迟不能代替 P95/P99。少量特别慢的请求会严重影响用户体验，却可能被平均值掩盖。

## 7. 一个完整的计算示例

某问题的标准法条为 `A、B`，系统前 5 条返回：

```text
第 1 名：X
第 2 名：A  <- 正确
第 3 名：Y
第 4 名：B  <- 正确
第 5 名：Z
```

因此：

| 指标 | 计算 | 结果 |
|---|---|---:|
| Recall@5 | `2 / 2` | 1.0 |
| Precision@5 | `2 / 5` | 0.4 |
| Hit@5 | 至少命中一条 | 1 |
| RR | 第一条正确结果排第 2，`1 / 2` | 0.5 |

假设生成答案包含 4 个法律主张，其中 3 个有引用，只有 2 个能被引用原文充分支持：

| 指标 | 计算 | 结果 |
|---|---|---:|
| Citation Coverage | `3 / 4` | 0.75 |
| Faithfulness | `2 / 4` | 0.50 |

这个例子说明：检索结果可以找得很全，但答案仍可能存在无依据结论；因此不能只用 Recall@5 判断整个 RAG 系统是否可靠。

## 8. 本项目当前已有结果

阶段 3 的正式报告位于 `data/eval/results/rerank_context_v1.json`。24 道可回答题的结果为：

| 方法 | Recall@1 | Recall@3 | Recall@5 | Recall@10 | MRR | P95 检索延迟 |
|---|---:|---:|---:|---:|---:|---:|
| Hybrid | 0.5625 | 0.7917 | 0.8542 | 0.9792 | 0.7639 | 399.8 ms |
| Rerank | 0.5417 | 0.8333 | 0.9375 | 0.9792 | 0.7583 | 2371.4 ms |

正确解读：

- Rerank 明显提高了前 5 条对标准法条的覆盖率；
- MRR 略微下降，说明第一条正确结果的平均位置没有同步改善；
- Recall@5 为 0.9375 只代表检索覆盖率，不代表最终答案正确率为 93.75%；
- 当前评测集较小，24 道检索题不能代表全部真实法律咨询场景；
- 当前引用校验能证明引用存在并来自证据，但还不能完整证明每个答案主张都被法条语义支持。

## 9. 推荐的评测组合

法律 RAG 的最低评测组合建议为：

| 目标 | 推荐指标 |
|---|---|
| 检索不漏法条 | Recall@5、Recall@10 |
| 结果少噪声 | Precision@5 或 Top-K 相关性 |
| 正确法条排在前面 | MRR、NDCG@5 |
| 最终结论可靠 | Answer Correctness、Completeness |
| 结论有充分依据 | Citation Validity、Citation Correctness、Citation Coverage、Faithfulness |
| 能安全处理未知问题 | 正确拒答率、过度拒答率、危险误答率 |
| 法律版本可靠 | 时效正确率、权威来源率、版本匹配率 |
| 满足生产体验 | P50/P95/P99 延迟、成功率、超时率、成本 |

上线门槛应按业务风险预先确定，并使用独立测试集验收。不能在同一批问题上反复调参后，再把该批问题的分数当作无偏的上线结论。
