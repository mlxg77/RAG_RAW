## 1. 实际完成内容

- 将评测集从 30 题扩充到 100 题；
- 原 q001～q030 标记为 development，新增 q031～q100 作为独立 holdout；
- 覆盖直接查询、口语场景、跨条文、跨法律、指定条号、事实不足和超范围拒答；
- 实现 `evaluate-system` CLI，一条命令运行真实检索、重排、生成和引用校验；
- 自动计算 Recall@1/3/5/10、MRR、nDCG@10、回答行为、引用和延迟指标；
- 同时输出机器可读 JSON 和便于审阅的 Markdown 报告；
- 报告保存评测集与语料 SHA-256、模型名、Prompt 版本、阈值和生成时间；
- 增加 `--split`、`--id`、`--limit` 和 `--fail-on-gates`，支持切片复评与 CI 门禁；
- 根据首轮评测校准生成提示词，减少不必要追问；
- 对模型偶发的空结构化结果增加一次受限重试。

## 2. 正式验收口径

质量门槛只使用 70 道 holdout，避免用已经参与阶段 2～4 调参的 30 道开发题自我验收。

正式命令：

```bash
uv run python -m rag_law.cli evaluate-system --split holdout --fail-on-gates
```

产物：

- `data/eval/results/answer_quality_v1.json`
- `data/eval/results/answer_quality_v1.md`

指标定义：

- 引用精确率：展示引用与本次上下文证据的 evidence ID、chunk、法律名、条号和原文全部一致；
- 伪造引用率：无法逐字段映射回本次证据的展示引用占比；
- 引用完整率：人工标注的核心法条中，被最终回答覆盖的比例；
- 核心法条标注精确率：展示引用落在非穷尽式核心法条标注中的比例，仅作诊断，不作为伪造引用判断；
- 不可回答题行为准确率：事实不足题返回追问、范围外题返回证据不足的比例。

## 4. 调优过程遇到的问题与解决方式

### 4.1 首版引用指标误伤真实辅助法条

- 现象：q031 的人工核心标注只有《社会保险法》第十条，模型同时引用了直接相关的第十二条；首版指标把第十二条记为错误引用，导致引用精确率只有 50%；
- 原因：人工 `expected` 是“最小核心法条集合”，不是所有可能相关法条的穷尽式 relevance judgment；把“未出现在 expected”直接等同于“伪造”会产生假阳性；
- 处理：拆分两个口径：
  - `citation_precision` 按 evidence ID、chunk、法律名、条号和引文是否能严格映射回本次上下文计算，用于正式引用门槛；
  - `expected_citation_precision` 只衡量展示引用落入核心标注集合的比例，作为诊断项；
  - `citation_recall` 继续衡量核心法条覆盖率；
- 结果：额外但真实的辅助引用不再被误判为伪造，同时仍能观察核心法条是否遗漏。

### 4.2 Prompt 过度触发追问

- 现象：首轮 70 题评测中，44 题返回 `needs_clarification`；整体行为准确率只有 30%，可回答题行为准确率只有 20%。许多“某条法律如何规定”的一般规则问题也被追问个人事实；
- 原因：阶段 4 Prompt 把“说明适用条件”和“缺少事实时追问”放在相邻规则中，模型倾向于把尚未查明个案事实一律视为必须追问；
- 处理：将 Prompt 升级为 `stage5-v1-behavior-calibrated`，明确：
  - 能说明一般规则时必须条件式直接回答；
  - `conditions` 用来列适用条件，不等于必须设置 `follow_up_question`；
  - 询问法律、条号、期限、主体范围或一般规则时不得追问个人情况；
  - 只有缺少的信息导致连一般规则都无法确定时才追问；
- 结果：q031 从错误追问恢复为 `answered`，最终可回答题行为准确率提高到 92.7%。

### 4.3 规则守卫虽然提高指标，但泛化方式不合理

- 现象：首轮不可回答题准确率为 66.7%；Prompt 调整后的 16 题切片复评中，模型又把多道事实不足题直接回答，并用主题相近证据回答《行政处罚法》、实时效力和未收录行政法规问题，不可回答题准确率一度降至 46.7%；
- 尝试：曾增加基于法律标题和若干正则表达式的 `QueryGuard`，把未收录法律、境外法、判例、实时效力及若干典型事实不足问法提前分流；该实验使 15 道不可回答题达到 15/15；
- 复盘：守卫直接枚举了有限问法和题型，容易误拦未覆盖表达，也会让 100% 指标带有针对 holdout 调规则的嫌疑。这种提升不能证明系统获得了通用范围判断能力；
- 最终处理：删除 `query_guard.py`、流水线接入和专属测试，不把该实验结果作为当前正式指标。后续应使用由 manifest 驱动的法律范围识别、独立范围分类评测或可泛化的分类组件，而不是继续扩充正则表。

### 4.4 远程模型偶发返回空结构化结果

- 现象：首轮正式评测有 7 题的 OpenAI 兼容 tool-call 返回 `None`，流水线原先立即降级为 `generation_failed`；
- 原因：远程结构化输出并非每次都返回可解析的 `GeneratedAnswer`，属于模型服务的瞬时稳定性问题；
- 处理：只对 `None` 这一明确的瞬时空结果原样重试一次；普通异常仍立即安全降级；若第二次仍为空则返回 `generation_failed`，总生成次数仍不超过 2；若已经使用两次机会，则不再进入引用修复，避免超过既定调用上限；
- 结果：无守卫最终正式评测中 q062、q083 两题连续两次为空，生成失败数为 2，且没有未经校验的内容被展示。

### 4.5 跨条文与跨法律召回仍是主要短板

- 现象：最终 Recall@10 为 90%，未命满核心法条的 9 道题主要集中在跨条文、跨法律场景；q070 仍只能召回《未成年人保护法》第七十四条和《民法典》第一百四十五条中的一条；
- 原因：单条自然语言查询通常突出一个争议点，BM25 与 Dense 候选都可能遗漏语义跨度较大的第二部法律或第二个法律效果；Reranker 只能重排已有候选，不能找回未进入候选集的法条；
- 处理：本阶段不继续在同一 holdout 上调参，避免对 70 题过拟合；保留逐题 Recall 和排名结果，后续优先尝试查询拆解、法律主题扩展和多查询召回；
- 结果：Recall@10 达到 V1 的 90% 门槛，但 q066、q070 等问题继续作为下一阶段定向优化样本。

## 5. 评测驱动的修复与复评过程

| 轮次 | 主要观察 | 采取措施 | 结果 |
|---|---|---|---|
| 首轮 holdout 70 题 | Recall@10 90%；不可回答准确率 66.7%；44 题被追问；7 题空结构失败 | 修正引用口径、校准 Prompt、增加空结果重试 | 一般规则问题恢复直接回答，结构失败明显减少 |
| 16 题行为切片 | q031 已正常回答，但仅靠 Prompt 时不可回答准确率 46.7% | 实验性增加 QueryGuard | 15 道不可回答题全部正确，但方案过窄 |
| 守卫方案复盘 | 指标提升依赖枚举题型和问法 | 删除 QueryGuard 及其测试 | 避免用狭隘规则换取表面高分 |
| 无守卫最终 holdout 70 题 | 不可回答准确率 53.3%，整体行为准确率 82.9% | 保留真实基线，不回填题型正则 | 4 项硬门槛通过，1 项未通过 |

最终原则是：引用是否真实继续由程序逐字段校验；范围识别需要由知识库元数据和独立可泛化能力驱动，不能通过不断增加面向评测题的正则规则来获得表面高分。

## 6. 已知限制与后续事项

- q062 和 q083 连续两次返回空结构化结果，最终安全降级为 `generation_failed`；
- q066 对“不缴社保后解除并补偿”仍返回追问；
- q070 仍只能召回两条核心法条中的一条，因而安全拒答；
- 9 道可回答题的 Recall@10 未达到 100%，跨条文与跨法律问题仍是主要短板；
- 事实不足题 q086～q089 没有稳定进入追问：q086 被低相关度阈值直接拒答，q087～q089 被模型直接回答；
- 范围外题 q094、q099、q100 被主题相近的高分证据带偏并直接回答；
- 核心法条标注是最小必要集合，不是所有相关辅助法条的穷尽式标注，因此不应把额外的真实辅助引用判为伪造；
- 当前报告基于远程模型单次运行，模型服务漂移可能导致回答行为和延迟波动。

后续版本保留 `--fail-on-gates` 作为严格质量检查，并优先设计由 manifest 和独立分类评测驱动的通用范围识别方案。不可回答题行为准确率达到 90% 仍是明确代办，但按 V1.0 收尾决策作为已知限制管理，不阻塞本版本完成。
