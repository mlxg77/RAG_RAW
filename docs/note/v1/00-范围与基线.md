## 4. 遇到的问题与解决方法

### 问题 1：第三方 OpenAI 兼容服务的 embedding 语义错乱（重要）

- 现象：接口调用成功、向量 1024 维，但相关句（"建立劳动关系应订立书面劳动合同" vs "公司必须与员工签书面合同"）相似度 0.3054，反而低于无关句（对比"机动车减速"）0.3938；
- 原因：langchain-openai 的 `OpenAIEmbeddings` 默认 `check_embedding_ctx_length=True`，会先用 tiktoken 将文本编码为 token id 数组再作为 input 发送（该设计面向 OpenAI 官方 API）；第三方服务用自身模型词表解释这些 id，得到语义乱码向量；
- 解决方法：显式传入 `check_embedding_ctx_length=False`，直接发送原始字符串；修复后相关句 0.8585、无关句 0.4493；
- 如何避免再次发生：接入任何非 OpenAI 官方的兼容服务都必须关闭该选项；embedding 健康检查不能只验证"接口能通"，必须断言"相关句相似度 > 无关句"的方向性。

### 问题 2：治安管理处罚法条号与旧版不同

- 现象：凭印象标注时写成旧版"第四十三条（殴打他人）"，核对原文发现为"第五十一条"；
- 原因：该文件为 2025 年修订版，条文序列变化；
- 解决方法：全部 45 处评测标注逐一与提取原文核对，不凭记忆写条号；
- 如何避免再次发生：法条内容与条号永远以仓库内原文为准；标注流程先提取原文再核对。

## 6. 可复用知识

- 第三方兼容 embedding 的 tiktoken 坑与修复（见第 4 节问题 1），适合作为所有兼容服务的默认配置；
- pydantic-settings 配置模式：绝对路径 `env_file` + `env_prefix` + 模块级实例化，实现 fail fast 与"从任意目录运行都正确"；
- 校验脚本模式：错误收集（不中断）→ 双向校验（正向查存在、反向查覆盖）→ `sys.exit(1)` 供自动化使用；
- 评测标注流程：起草问题 → 提取全部原文 → 逐条核对条号 → 程序化校验（ID 唯一、名称与 manifest 一致、条号格式、拒答题 expected 为空）；
- `uv run --with <pkg>` 可临时带依赖跑一次性脚本，不污染项目依赖。
