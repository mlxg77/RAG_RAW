# 阶段 6：接口、界面与部署：实施笔记

## 实际交付

- 提供 FastAPI 应用 `rag_law.api.main:app`：`GET /v1/health`、`GET /v1/laws`、`POST /v1/retrieve`、`POST /v1/query`。
- `/v1/query` 复用 `AnswerPipeline`，返回阶段 4 定义的 `AnswerPipelineResult`；`/v1/retrieve` 返回精排后的法条结果。
- API 延迟加载模型与索引，启动和健康检查不读取密钥。健康检查分别报告 manifest、结构化法条、BM25 和 Chroma 是否就绪。
- 提供每 IP 每分钟 30 次的进程内限流与 60 秒请求超时；索引/服务不可用返回 503，超时返回 504，限流返回 429。
- 演示界面已经支持连续问答、法律筛选、法条位置展示和上传法律后的全链重建；CLI 的 `add-document` 仍是等价管理入口。

## 隐私与运行边界

`AnswerRunLogger` 写 JSONL 前递归脱敏身份证号、手机号、邮箱、银行卡号和座机号。API 的异常日志只记录异常类型，不记录用户查询原文。

本地以 `uv run uvicorn rag_law.api.main:app --host 127.0.0.1 --port 8000` 启动；详细配置、重建索引与排障说明见 README。进程内限流不适用于多实例部署，生产环境应由反向代理或共享限流存储接管。

## 验证

增加 `tests/test_api.py`，覆盖健康检查、法律清单、检索 schema、非法法律筛选、超时和限流。静态编译与 OpenAPI schema 已在本地验证。当前受执行环境限制：其 Python 线程执行器会阻塞，因而依赖 `TestClient` / `asyncio.to_thread` 的端到端测试未能在此沙箱完成；在正常本地环境用 `uv sync && uv run pytest tests/test_api.py -q` 验证。
