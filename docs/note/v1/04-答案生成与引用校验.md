## 1. 实际完成内容

- 使用 `ChatOpenAI` 接入 SiliconFlow `Qwen/Qwen3-8B`；
- 使用 `ChatPromptTemplate` 定义首次回答和引用修复两套提示词，提示词版本为 `stage4-v1`；
- 使用 Pydantic `GeneratedAnswer` 和 `with_structured_output` 约束结构化输出；
- 使用 LCEL 组合 Prompt 与结构化 LLM；
- 实现结论、分析、适用条件、引用、限制和追问字段；
- 模型只引用 `E001` 等短 Evidence ID，程序映射回原始 `chunk_id`；
- 严格校验证据 ID、法律名称、条号、展示证据连续子串和原始法条连续子串；
- 引用校验失败时只修复一次，再失败时返回安全降级结果；
- 设置临时 Top1 Rerank 拒答阈值 `0.15`；
- 实现 `answered`、`needs_clarification`、`insufficient_evidence` 和 `generation_failed` 四种状态；
- 新增 `answer` CLI，支持法律名称过滤、阈值覆盖、调试输出和 JSON 输出；
- 新增 JSONL 运行日志，记录模型、Prompt、检索元数据、结果状态与延迟；
- 对身份证号、手机号、银行卡号、邮箱和座机号进行递归脱敏；
- 日志不保存完整上下文、检索正文、API Key 或原始校验错误；
- 完成 96 项自动化回归测试和 7 条真实链路验收。

## 2. 最终实现方案

### 回答流水线

```text
用户问题
  -> 阶段 3 混合检索、精排和上下文构建
  -> Top1 低于 0.15：直接返回 insufficient_evidence
  -> 首次结构化生成
  -> 引用校验
      -> 通过：构造最终 AnswerResponse
      -> 失败：携带错误和原回答修复一次
          -> 通过：构造最终 AnswerResponse
          -> 再失败：返回 generation_failed
  -> 写入脱敏 JSONL 运行日志
```

模型生成的引用结构只包含 `evidence_id`、法律名、条号和引文。通过校验后，程序使用原始法条元数据构造 `ValidatedCitation`，补充 `chunk_id`、`law_id`、来源文件和页码。模型不能直接决定最终展示的追溯字段。

### 低相关度门控

当前临时阈值为 `0.15`。阶段 3 的 24 道可回答题中，已知召回失败的 q019 Top1 为 `0.0176`，其余题最低 Top1 约为 `0.238`，因此暂取两者之间的值。真实验收表明，单一相关度阈值不能识别所有范围外或事实不足问题，阶段 5 必须重新校准并加入显式范围判断。

### 运行日志

默认写入：

```text
logs/answer_runs.jsonl
```

每行是一条独立 JSON，包含运行 ID、UTC 时间、脱敏问题、法律过滤条件、Prompt 版本、模型名、检索结果元数据、脱敏最终回答和延迟指标。`logs/` 已被 Git 忽略。

## 4. 遇到的问题与解决方法

### 问题 1：模型为法律名称添加书名号

- 现象：q002 检索正确命中《道路交通安全法》第九十一条，但模型在 `law_name` 中加入外层书名号，严格字符串校验失败；修复一次后仍重复；
- 当前处理：不放宽校验，第二次失败后安全降级；
- 后续：在阶段 5 对比强化 Schema 描述、提示词示例，以及仅规范化外层书名号三种方案。

### 问题 2：事实不足题没有形成追问

- 现象：q025、q026 均进入两次生成后降级，最终没有返回 `needs_clarification`；
- 当前处理：保留安全降级结果；
- 后续：增加显式回答模式字段或生成前事实充分性判断，并把追问准确率纳入评测。

### 问题 3：相似主题的范围外问题可能获得高分

- 现象：q030 指定不在库中的《个人信息保护法》，Top1 仍达到 `0.707569`；
- 原因：现有身份证法等文本与“个人信息、人脸识别”在语义上相关，相关度阈值不能等同于知识库范围判断；
- 当前处理：模型失败后安全降级；
- 后续：从问题中抽取显式法律名称，并先与 `manifest.yaml` 中的正式名称对比。

### 问题 4：失败路径延迟较高

- 现象：q025 总耗时达到 228.8 秒；
- 原因：阶段 3 包含多次远程 Rerank，LLM 客户端存在传输重试，引用失败后又执行一次修复生成；
- 后续：分别记录单次 LLM 延迟和传输重试次数，重新设置超时，避免多层重试叠加。

## 5. 实验和决策记录

| 方案 | 结果 | 是否采用 | 原因 |
|---|---|---|---|
| `with_structured_output` + function calling | 能返回 Pydantic 对象 | 采用 | Schema 会随工具调用发送给模型 |
| 模型直接输出完整 chunk_id | 尚未使用 | 否 | 长 ID 容易复制错误且浪费上下文 |
| 模型引用短 Evidence ID | 可映射到原始 chunk | 采用 | 便于生成和严格校验 |
| 引用失败无限重试 | 延迟和成本不可控 | 否 | 最多修复一次 |
| 单一 Rerank 阈值作为范围判断 | q030 得分 0.707569 | 临时保留 | 阶段 5 增加显式范围判断 |
| 保存完整 Prompt 和上下文 | 存储量大且增加隐私风险 | 否 | 只记录 Prompt 版本和检索元数据 |
| 当前真实模型表现阻塞阶段收尾 | 4/7 用例未达期望 | 否 | 按项目决策转为明确代办，进入阶段 5 量化处理 |

## 6. 可复用知识

- 结构化输出只保证字段形状，不保证字段值与证据完全一致，仍必须程序校验；
- Evidence ID 应由程序分配，最终 chunk 映射也应由程序完成；
- 低相关度阈值适合快速拒绝明显无关问题，但不能代替知识库范围识别；
- 对模型生成字段进行严格校验时，要明确决定哪些差异属于格式差异，哪些属于事实差异；
- 传输重试和业务重试必须分别计数，否则失败路径延迟可能成倍放大；
- 运行日志应默认最小化，只保存复现和评测必需的数据。
