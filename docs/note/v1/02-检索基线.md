## 1. 实际完成内容

- 使用 jieba 和 rank-bm25 实现中文 BM25 检索；
- 使用 `BAAI/bge-m3` 和 `langchain-chroma` 实现向量检索；
- 建立持久化的 `law_articles` Chroma collection；
- BM25 和 Dense 使用相同的增强检索文本，包括法律名、编、章、节、条号和正文；
- 使用 `chunk_id` 将检索结果映射回原始 `ArticleChunk`，确保返回正文不包含检索增强标题；
- 实现按正式法律名称过滤；
- 实现 Reciprocal Rank Fusion 混合检索；
- 实现统一检索 CLI；
- 实现 Recall@1/3/5/10、MRR、P50/P95 延迟评测；
- 保存初始基线、融合调参、调优结果和重建后验证报告；
- 记录数据哈希、Embedding 模型、依赖版本和索引版本；
- 为 BM25、Dense、Chroma 持久化、法律过滤、RRF、评测指标和参数搜索编写自动化测试。

## 2. 最终实现方案

### 检索文本

索引文本由以下字段拼接：

```text
法律名称
编
章
节
条号
法条正文
```

检索结果通过 `chunk_id` 映射回 `articles.jsonl` 中的原始法条，返回给调用方的 `text` 仍然是原始正文。

### BM25

- 中文分词：jieba 0.42.1；
- BM25 实现：rank-bm25 0.2.2；
- 分词方案标识：`jieba-accurate-v1`；
- 索引位置：`indexes/bm25/bm25_index.json`；
- 保存法条和分词结果，加载时重新构造 `BM25Okapi`，不使用 pickle。

### Dense

- Embedding 模型：`BAAI/bge-m3`；
- 模型供应商未返回独立的模型 revision，因此当前只能记录模型标识与客户端依赖版本，无法锁定远程部署的精确构建版本；
- 接口：SiliconFlow OpenAI 兼容接口；
- LangChain 集成：`langchain-openai`；
- 向量库：`langchain-chroma`；
- Collection：`law_articles`；
- 距离类型：cosine；
- 持久化位置：`indexes/chroma/`；
- 文档 ID：`chunk_id`；
- 批量写入大小：32。

### Hybrid

最终参数：

```text
candidate_top_k = 10
rrf_k = 60
bm25_weight = 1.0
dense_weight = 2.0
final_top_k = 10
```

RRF 公式：

```text
score = Σ weight / (rrf_k + rank)
```

原始 BM25 和 Dense 分数不直接相加，因为两者量纲不同。

## 4. 遇到的问题与解决方法

### 问题 1：等权 RRF 被较弱的 BM25 拖累

- 现象：初始等权 Hybrid Recall@10 为 0.9167，低于 Dense 的 0.9792；
- 原因：口语场景和跨法律问题中，BM25 的召回明显弱于 Dense，等权融合让部分 Dense 正确结果跌出前 10；
- 解决方法：缓存两路前 50 候选，在不重复调用 Embedding API 的情况下执行小规模参数网格搜索；
- 最终参数：`candidate_top_k=10`、`rrf_k=60`、`bm25_weight=1.0`、`dense_weight=2.0`；
- 最终效果：Hybrid Recall@10 与 Dense 持平，MRR 和前排 Recall 更高。

### 问题 2：q019 无法完整召回两个标准法条

- 现象：未成年人保护法第七十四条可以召回，民法典第一百四十五条在 BM25 和 Dense 前 50 中均未出现；
- 原因：问题使用“孩子、游戏充值、退款、平台”等表达，而民法典第一百四十五条使用“限制民事行为能力人、法定代理人追认、撤销”等抽象法律概念，词汇和表层语义距离较大；
- 解决方法：本阶段不伪造候选、不修改标注、不通过过度调权掩盖问题；
- 后续方向：查询拆解、法律术语扩展或多查询召回；
- 结论：RRF 只能重排已有候选，不能找回两路均未召回的法条。

### 问题 3：重新 Embedding 后近分候选顺序漂移

- 现象：相同数据、模型配置和索引参数重建后，共有 5 道 Dense 查询的 Top10 出现边界候选替换，并传播为 5 道 Hybrid 排名差异；
- 具体影响：核心 Recall@10 完全一致；Hybrid MRR 从 0.7653 变为 0.7639；Hybrid Recall@5 从 0.8750 变为 0.8542；
- 原因：远程 `BAAI/bge-m3` 重新计算文档向量时存在约 1e-4 量级的数值漂移，近分候选可能发生换位；
- 验证：在同一个重建后索引上，对 q004、q006、q020、q021、q023 分别连续查询三次，结果全部稳定；
- 当前处理：保证数据身份、模型配置和质量指标可重复，不承诺远程文档重新 Embedding 后所有非关键候选逐项、逐序完全一致；
- 后续若要求严格复现：需要缓存文档向量、固定可版本化模型服务或使用确定性的本地 Embedding 模型。

### 问题 4：PDF 正文仍有少量视觉断行

- 现象：民法典第一百四十五条中存在“精\n神”“有\n效”等词内换行；
- 影响：当前检索指标仍达标，但可能影响后续连续子串引用校验；
- 当前处理：记录为遗留问题；
- 后续要求：阶段 4 引用校验前修复文本标准化并重建索引。

## 5. 实验和决策记录

| 方案 | 结果 | 是否采用 | 原因 |
|---|---|---|---|
| 仅使用 BM25 | Recall@10 0.7083 | 否 | 口语与跨法律问题召回不足 |
| 仅使用 Dense | Recall@10 0.9792，MRR 0.7028 | 作为单路基线 | 召回强，但精确词信号没有充分利用 |
| BM25/Dense 等权 RRF | Recall@10 0.9167，MRR 0.6911 | 否 | BM25 对部分问题产生负面影响 |
| Dense 权重 2.0 | Recall@10 0.9792，MRR 0.7639 | 采用 | 保持 Dense 召回，并改善前排质量 |
| Dense 权重 3.0 | 开发集指标与 2.0 相同 | 否 | 更高权重没有额外收益，选择更保守的 2.0 |
| 每路候选 10 条 | 网格搜索中表现最佳 | 采用 | 指标更好且查询开销较小 |
| 使用原始分数直接相加 | 分数量纲不同 | 否 | BM25 与余弦分数不能直接比较 |
| 缓存候选后离线调参 | 只需一次 Dense 查询 | 采用 | 避免重复 API 调用 |
| 修改 q019 标注以提高分数 | 会污染评测可信度 | 否 | 保留真实困难样本 |

## 6. 可复用知识

- 中文法律检索不能只依赖 BM25，口语场景需要语义召回；
- RRF 的价值是组合排名，不是统一不同检索器的原始分数；
- 当两个检索器强弱差异明显时，等权 RRF 不一定优于最佳单路；
- 应先缓存候选，再离线搜索 RRF 参数，避免重复调用远程 Embedding；
- 多法条问题应按召回法条比例计算 Recall，不能命中任意一条就算完全成功；
- RRF 无法解决候选生成阶段完全未召回的问题；
- 远程 Embedding 的模型名称相同不代表重新计算的浮点向量逐位一致；
- 检索可重复性应区分索引内重复查询稳定性、重建后的质量稳定性和逐项排序一致性；
- 原始法条正文与检索增强文本应分离，避免后续引用错误。
