# 阶段 6：接口、界面与部署

> 版本：V1  
> 状态：done

## 阶段目标

把经过评测的 RAG 链路封装为 API 和可演示界面，并补齐基本运行、日志和隐私保护能力。

## 实施任务

- [x] 实现 `/v1/query`、`/v1/retrieve`、`/v1/laws` 和 `/v1/health`。
- [x] 实现指定法律增量重建索引接口或管理命令。
- [x] 在演示界面提供基于现有 manifest 和原始文件的一键全库重建按钮。
- [x] 使用 Streamlit 建立演示界面。
- [x] 展示结论、限制、法条原文及原始文件位置。
- [x] 增加超时、限流、错误处理和健康检查。
- [x] 对日志中的身份证号、手机号等敏感信息脱敏。
- [x] 编写本地运行、配置、重建索引和故障排查说明。
- [x] 提供基于锁定依赖的 Docker 镜像构建文件。
- [x] 提供同时运行 API 与 Streamlit 界面的 Docker Compose 配置。
- [x] 通过 bind mount 持久化语料、索引和脱敏日志，并为两个服务配置容器健康检查。

## 验收标准

- [x] API schema 稳定并有自动化测试。
- [x] 用户可从界面完成提问并查看法条依据。
- [x] Chroma 和 BM25 数据重启后仍可使用。
- [x] 缺少模型密钥或索引时能返回明确错误。
- [x] 日志不记录用户敏感信息原文。
- [x] Compose 配置可被 YAML 解析，API 与界面均有独立端口、挂载和健康检查。
- [x] 容器重建后可继续使用宿主机上的 Chroma、BM25 和日志数据。
